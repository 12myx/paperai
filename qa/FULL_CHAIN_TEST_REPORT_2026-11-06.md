## 3. 新发现问题（只记录，未修复）

### U1. 批量上传完成后，侧栏研究空间统计不刷新（中）

**复现：**

1. 新账号一次上传 2 篇 PDF；
2. 等待两篇解析完成；
3. 首页正文显示“2 篇可检索论文”；
4. 左侧底部“研究空间”仍显示：

```text
0 论文
0 页解析
```

截图：`qa/screenshots/19-multi-upload.png`

**原因判断：** `Shell` 的 `/settings/usage` 只在 location 变化时加载；Uploader 完成后 Home 只刷新论文列表，没有通知 Shell 刷新 usage。  
**影响：** 用户刚上传成功，侧栏统计仍为 0，产生“是不是没上传成功”的疑虑。  
**本次未修复。**

### U2. 部分文件失败时，批次成功提示会掩盖失败（中）

**复现：**

1. 同一批选择一篇合法 PDF + 一篇损坏 PDF；
2. 合法论文解析完成，损坏论文任务失败；
3. 上传面板在成功后关闭；
4. 首页只体现成功论文，失败文件只在资料库中显示失败标记。

实测：

```text
资料库 paper-card = 2
failed badge = 1
上传面板已关闭
```

截图：`qa/screenshots/19d-partial-upload.png`

**原因判断：** `Uploader` 的批次完成逻辑在 `completed.length > 0` 时只发送成功 toast 并调用 `onUploaded`；失败数量没有进入完成提示。  
**影响：** 用户可能误以为全部成功；需要进入资料库才发现某一篇失败。  
**本次未修复。**

## 6. 结论

多文件上传功能已达到可用状态，单文件上传未回归，原有功能 QA 与后端测试均通过。

当前保留两个新 UX 缺陷 U1/U2，按要求只记录、不自动修复。建议下一轮优先处理：

1. 上传完成后刷新 Shell usage；
2. 批次完成提示明确显示“成功 N / 失败 M”，并在面板关闭前给失败项一个可停留的摘要；
3. 如需真正并行解析，应迁移到 PostgreSQL + 多 worker 队列，而不是在 SQLite 上开多 worker。
