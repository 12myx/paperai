# 05 · 最短启动提示词（时间紧时用）

> 目标：让码道一次性产出**可运行的垂直切片**，先跑通“登录 → 上传 PDF → 阅读 → 提问 → 引用”，再用阶段提示词补齐。
> 如果你的码道支持 Agent/工作区模式，直接整段发送；否则拆成后端/前端两次。

---

```text
你是资深全栈工程师。请在空工作区从零实现 PaperLens AI 的可运行垂直切片。技术栈固定：Python 3.12 + FastAPI + SQLAlchemy 2 + SQLite；React 18 + TypeScript + Vite；PDF 用 PyMuPDF 解析、pdf.js 渲染；测试用 pytest。

产品定位：面向研究生/科研人员的可追溯 AI 论文阅读助手。所有回答必须基于论文原文，并带页码引用。

必须一次交付、可直接运行：

【后端】
1. 配置、数据库、用户表；bcrypt 密码；JWT 登录；所有资源按 user_id 隔离。
2. POST /api/papers 上传 PDF（校验 %PDF、≤50MB），后台解析：页码、章节、段落、切片（保存 page_start/end、section、bbox、text）；GET /api/papers、GET /api/papers/{id}、GET /api/papers/{id}/file、GET /api/papers/{id}/outline。
3. 检索：BM25 + 中文字符 bigram；返回 C1..Cn 引用（论文、页码、章节、原文）。
4. POST /api/chat/stream：SSE 事件 start/step/delta/done；无模型 Key 时走“本地抽取模式”，从检索片段生成带 [C#] 的回答，并明确标注；有 DEEPSEEK_API_KEY 时调用 OpenAI 兼容接口。
5. 批注 CRUD：POST/GET /api/annotations，保存页码、颜色、quote、rects、note；刷新可恢复。
6. GET /api/health。

【前端】
1. 登录/注册页；登录后进入 /app。
2. 论文库：上传、列表、打开阅读。
3. 阅读器：pdf.js 连续渲染（带 Authorization 拉取文件）、目录/页码、选中文字浮动工具条（5 色高亮）、批注保存与恢复、右侧 AI 总结/提问（SSE）、引用点击回到页码。
4. 设计：浅色学术风，背景 #F7F6F2、卡片 #FFF、强调 #2C6B5D、字体 Inter/PingFang SC；不要用 UI 框架；桌面 + 移动端可用。

【质量】
- 不要假数据、假按钮、TODO；不能运行的功能不要放进 UI。
- 错误要有可读提示；上传/解析/模型失败不能崩溃。
- 写 5 个以上 pytest：注册登录、上传解析、检索引用、SSE 回答、批注持久化。
- README 写清启动命令；提供 .env.example。

【输出】
1. 目录树；2. 完整文件代码；3. 启动与测试命令；4. 已实现/未实现清单。

不要询问我细节；按最可靠方案自主实现。先输出计划，再写代码。
```
