# 04 · 执行手册：码道怎么用、证据怎么留、包怎么交

> 这份是给你（人）看的，不是给码道看的。目标：用最短时间真实完成“码道复刻 + 赛题材料”。

---

## 1. 开始前 30 分钟

1. 注册/登录华为云，开通 CodeArts，安装码道 IDE 插件（或使用 CodeArts IDE）。
2. 新建一个空工作区 `paperlens-ai`。
3. 建好 Git 仓库；配置用户名/邮箱（不要用隐私邮箱）。
4. 建好证据目录 `codearts_proof/` 五个子目录。
5. 准备演示数据：2 篇公开论文 PDF（建议 arXiv），一篇中文/一篇英文更好；不要用未授权论文。
6. 准备模型 Key（DeepSeek 或华为云兼容端点）。**只配置在应用设置或环境变量，不要出现在截图/视频**。
7. 录屏软件（OBS/系统录屏）、截图工具、PPT 模板。

---

## 2. 码道使用协议（保证证据真实可讲）

### 每条 Prompt 的标准动作

1. 截图：IDE + Prompt 输入框 + 当前文件树。
2. 发送 Prompt。
3. 等码道生成/修改；截图生成结果或 diff。
4. 本地运行验证命令；截图终端结果。
5. 如果有报错：截图报错 → 把报错原文贴给码道 → 截图修复 → 再跑验证。
6. Git commit：`phaseX: 功能描述 + 验证结果`。
7. 把 Prompt 摘要、产出、验证结果登记到 `prompt_log.md`。

### 五类必须有的证据

| 类型 | 至少几张 | 内容 |
| --- | --- | --- |
| 环境搭建 | 3 | 插件安装、项目初始化、依赖安装成功 |
| 代码生成 | 6 | 后端/前端/Agent/阅读器关键 Prompt + 生成结果 |
| 调试排错 | 3 | 真实报错 + 定位 + 修复后测试通过 |
| 测试验收 | 4 | pytest、浏览器 QA、移动端、导出文件 |
| 文档材料 | 3 | 码道生成 README/PPT 文案/视频脚本 |

> 评委看的是“过程”，不是“截图数量”。每张图最好能对应一个阶段和一次验证。

### 不要做的事

- 不要用其他 AI 生成后补拍码道截图；
- 不要 P 图改日期/改输出；
- 不要把 API Key、密码、身份证、手机号拍进去；
- 不要只截“成功”，不留报错与修复（反而显得不真实）。

## 3. 如果要从现有 PaperLens 复刻：参考实现审计提示词

> 你手上已有本项目源码。最稳妥的方式是让码道**审计并按模块重建**，而不是让它凭空猜。
> 把源码 zip 作为工作区附件/参考目录，然后发送下面这段。

```text
工作区里有一份 PaperLens 参考实现（backend/ 与 frontend/）。不要直接复制粘贴全部代码；请先做“可复刻审计”，再按模块重建。

第一步：输出审计报告
1. 目录树与模块职责；
2. 数据模型清单（表、字段、关系）；
3. API 清单（方法、路径、请求/响应要点）；
4. 前端路由与页面组件清单；
5. 设计 Token（颜色、字体、圆角、布局尺寸）；
6. 核心算法（PDF 解析、切片、检索、Agent 工具循环、SSE 协议）；
7. 测试清单与验收标准；
8. 你认为实现中最容易出错的 10 个点。

第二步：输出“复刻计划”
- 按依赖顺序拆成 10-12 个阶段；
- 每阶段的文件、验收命令、风险；
- 明确哪些部分需要我提供 Key/账号。

第三步：等我确认后再开始阶段 1。
不要修改任何文件，先只输出审计与计划。
```

### 复刻完成后的“差异校验”提示词

```text
请对照参考实现与当前工作区，输出差异矩阵：
1. 功能：缺失/行为不一致；
2. API：路径、字段、状态码差异；
3. 页面：路由、组件、交互差异；
4. 视觉：颜色、字号、间距、圆角、响应式断点；
5. 测试：覆盖缺口；
6. 安全：隔离、校验、密钥处理差异。

按 P0（阻断演示）/P1（影响评分）/P2（可选）排序，并给出修复步骤。
先不要改代码，输出矩阵与修复计划。
```

## 5. 演示数据准备（重要）

评委看的是“真实感”，不是空库。

建议准备：

- 2 篇 arXiv 论文（1 篇 RAG/检索，1 篇同方向对比）；
- 1 个合集「RAG 阅读清单」；
- 1 个研究项目「毕业设计文献调研」；
- 3-5 条批注（不同颜色）；
- 2 条知识（一条方法、一条结论）；
- 1 段完成的对比报告；
- 1 个导出的 DOCX/PDF。

如果使用 `backend/scripts/qa_seed.py`，它会创建 QA 账号与示例数据；**提交前把演示账号改成不含个人信息的邮箱**。

---

## 6. 3 分钟视频拍摄清单

- 分辨率 1920×1080，浏览器 100% 缩放，关闭通知/微信；
- 提前登录，准备好 2 篇论文、1 个合集、1 个项目；
- 先录一条完整的，再补特写；
- 旁白语速 240-260 字/分钟，3 分钟约 750 字；
- 关键动作停顿 1 秒：引用回跳、刷新后高亮恢复、DOCX 打开；
- 不要展示设置页的 Key 输入框（可提前打码/跳过）；
- 片尾加 3 秒 Logo/队伍信息。

## 7. 打包命令（Windows）

> 如果系统禁止运行脚本：`powershell -ExecutionPolicy Bypass -File .\competition\prepare_submission.ps1 -TeamName "队伍" -Contact "联系方式"`
> 脚本会自动生成五目录、复制源码、检查缺失材料并打包。

先建临时目录：

```powershell
$stage = "C:\paperlens-submit\submission"
$root  = "C:\Users\14890\Documents\deepseek-harness\default-workspace\paperlens-ai"
New-Item -ItemType Directory -Force -Path $stage\ppt,$stage\project,$stage\video,$stage\codearts_proof,$stage\readme | Out-Null

# 复制源码（排除大目录与私有数据）
robocopy $root\backend  $stage\project\paperlens-ai\backend  /E /XD __pycache__ .venv data /XF *.db *.db-wal *.db-shm
robocopy $root\frontend $stage\project\paperlens-ai\frontend /E /XD node_modules dist .vite
Copy-Item $root\Dockerfile,$root\docker-compose.yml,$root\.env.example,$root\README.md -Destination $stage\project\paperlens-ai\
Copy-Item $root\docs -Destination $stage\project\paperlens-ai\docs -Recurse
```

然后手动放入：

- `ppt/PaperLens_作品介绍.pdf`
- `video/PaperLens_功能演示.mp4`（或 `视频链接.txt`）
- `codearts_proof/` 五类真实截图 + README + prompt_log
- `readme/作品说明文档.pdf` + 一键安装脚本 + 开源组件清单

最后压缩：

```powershell
$name = "PaperLens知研_队伍名称_v1.0.0_联系方式"
Compress-Archive -Path "$stage\*" -DestinationPath "C:\paperlens-submit\$name.zip" -Force
```

> 压缩包打开后第一层必须是五个文件夹，不要多套一层。

## 8. 提交前手动检查（逐项打勾）

### 代码与运行

- [ ] 干净目录下按 README 能启动
- [ ] `/api/health` 返回 ok
- [ ] 注册/登录正常
- [ ] 上传 2 篇 PDF 均解析成功
- [ ] 阅读器能渲染、选中高亮、刷新恢复
- [ ] 对话带引用，引用能跳回页码
- [ ] 多论文对比有来源
- [ ] 知识库/图谱/项目可用
- [ ] 导出 PDF/DOCX 能打开
- [ ] 移动端 390px 不遮挡

### 材料

- [ ] PPT 覆盖：场景、架构、亮点、码道应用
- [ ] 视频 ≤3 分钟，声音清楚
- [ ] readme 覆盖赛题四项
- [ ] codearts_proof 五类证据 + 索引 + 日期
- [ ] 一键安装脚本能跑
- [ ] 开源组件清单含 License

### 安全与合规

- [ ] 包内无 `.env`、无 Key、无数据库密码
- [ ] 包内无个人手机号/身份证
- [ ] 论文为公开可引用材料
- [ ] 证据真实，无伪造
- [ ] 提交后保存提交成功截图

## 9. 答辩现场准备

- 准备离线可运行的版本（Docker 或本地），避免现场网络问题；
- 准备一个 5 分钟的“极简演示路径”：登录 → 打开论文 → 提问 → 引用回跳 → 高亮 → 导出；
- 准备一张架构图与一张“引用链路”图；
- 准备 2 个真实排错故事（码道怎么帮你定位）；
- 提前想好“没有 Key 怎么办”：现场切换本地抽取模式，说明这是诚实降级。

## 10. 常见问题

| 问题 | 处理 |
| --- | --- |
| 码道上下文装不下完整项目 | 用阶段提示词，每次只给它相关文件与验收标准 |
| 生成代码跑不起来 | 把完整报错贴回去，要求“先定位再改”，不要让它重写全文件 |
| 前端样式跑偏 | 给它设计 Token 与参考截图，要求只改 CSS |
| 端口冲突 | `Get-NetTCPConnection -LocalPort 8000` 找到进程并停止 |
| PDF 解析失败 | 检查是否加密/扫描版；用公开 arXiv PDF 演示 |
| SSE 不流式 | 确认没有代理缓冲；本地 uvicorn 直连 |
| 提交包太大 | 排除 node_modules/.venv/data/dist；视频用链接替代 |
| 每天只能提交 1 次 | 先在本地完整演练，再提交 |
