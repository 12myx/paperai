## 3. 参赛作品叙事建议

### 一句话定位

> **PaperLens 知研：让每一条 AI 科研结论都能回到论文原文。**

### 场景痛点（高校 / 实验室）

1. 研究生每周要读 5–15 篇论文，读不完、记不住；
2. 通用 AI 摘要无法追溯页码，不能直接用于综述与开题；
3. 读过的结论散落在聊天记录、PDF 批注和笔记软件里，无法形成长期资产；
4. 多篇论文之间缺少结构化对比，研究缺口靠“感觉”。

### 差异化创新（答辩重点）

1. **证据契约**：每个切片保存页码、章节、字符偏移和边界框；回答必须带 `[C1]` 引用，点击回到 PDF 对应页。
2. **诚实的降级**：没有模型 Key 时切换“本地抽取模式”，只抽取真实原文并明确标注，绝不伪造 AI 结果。
3. **写操作确认**：AI 保存知识、批注、导出文件前必须用户确认，模型不能静默写库。
4. **多论文片段对比**：用户可从不同论文手动挑选方法/实验片段，做证据级比较。
5. **长期研究资产**：批注、知识、项目、对话、导出记录全部持久化，并形成知识图谱。
6. **提示注入防护**：论文正文只作为“被引用资料”，不作为系统指令。

### 华为云能力叙事

- **码道**：全流程核心 AI 编程工具（环境搭建、代码生成、排错、测试、文档）。
- **可选华为云 OBS**：把 PDF/图表存储从本地磁盘切换为对象存储（提供适配层与环境变量；没有凭证时回退本地）。
- 不要编造未使用的华为云服务；没有接入就写“预留适配”。

## 5. 手动 vs 码道：分工表

| 工作 | 谁做 | 说明 |

| 注册华为云 / 码道、创建工程 | 手动 | 账号、实名、插件安装 |

## 7. 真实性红线

赛题明确要求“使用证明材料的完整性与真实性”。请务必：

- 在码道中真实发起对话、真实生成/修改代码；
- 截图包含 IDE 界面、Prompt、生成结果/报错与修复；
- Prompt 日志与 Git 提交时间线能互相印证；
- 不要用其他工具生成后伪造成码道记录。

如果现有代码来自其他工具，最稳妥的做法是：**用码道重新实现核心模块（或深度重构），保留真实的评审、修改、测试过程**。这既是合规要求，也能让答辩时讲得清楚。
