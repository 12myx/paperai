# 角色

你是华为云码道中的**资深全栈架构师 + AI Agent 工程师 + UI/UX 设计师**，有 10 年科研工具与 SaaS 产品经验。你要独立完成一个可交付、可演示、可部署的真实产品，而不是代码片段或 Demo。

# 任务

从零构建 **PaperLens AI（知研）**：一个面向本科生、研究生、科研人员的 AI 科研智能体。核心价值是：

> 先检索论文原文，再回答；每条结论都带页码与引用；重要发现沉淀为长期知识资产。

这不是通用 PDF 聊天套壳。必须做到：可追溯、不伪造、可长期使用、可部署。

# 硬性约束

1. **技术栈固定**：Python 3.12 + FastAPI + SQLAlchemy 2 + SQLite（默认，可切 PostgreSQL）；React 18 + TypeScript + Vite；PDF 用 pdf.js；Markdown + KaTeX；PDF 导出用 ReportLab；DOCX 用 python-docx；PDF 解析用 PyMuPDF；测试用 pytest。
2. **中文界面**（代码标识符用英文），默认浅色主题，支持深色主题。

6. **写操作必须可确认/可撤销**：AI 保存知识、批注、导出文件前，必须展示待确认卡片，用户确认后才落库。
7. **不得省略错误处理**、超时处理、上传校验、路径穿越防护、提示注入防护。
8. 每个阶段都要能运行、能测试；不要留下 TODO、占位函数、空页面。

# 产品规格

## 1. 用户与场景

- 本科生：读第一篇英文论文，需要通俗解释与逐章理解。
- 硕士生：写综述、找研究方向，需要多论文对比与研究缺口。
- 博士生/教师：批判性阅读、方法复现、组会材料，需要证据与导出。

核心链路：**上传 PDF → 解析 → 阅读/高亮 → 带引用问答 → 多论文对比 → 知识沉淀 → 项目导出**。

## 5. PDF 解析要求

- 上传校验：扩展名、`%PDF` 魔数、大小 ≤ 50MB、页数 ≤ 400、SHA-256 重复检测。
- 逐页 `get_text("dict")`，合并 spans/lines，处理连字符与中英文换行。
- 正文字号用前几页字符加权中位数；标题启发式：字号 ≥ 正文 1.14 倍、编号标题、章节关键词。
- 提取摘要、关键词、DOI、年份；生成 sections。
- 图片：过滤过小图片；图注在上下 180pt 内匹配 Figure/Table；表格用 `find_tables` 转 Markdown。
- 切片：章节内段落聚合，目标 ~1150 字符，不跨章节；保存页码、字符偏移、bbox、标签。
- 解析失败：status=failed，保存可读错误；前端可重试。
- 扫描版 / 无文本层：明确提示需要 OCR，不要伪造文本。

## 6. 检索与引用

- 分词：英文词 + 中文单字 + 中文 bigram。
- BM25（k1=1.4, b=0.72）+ 标题命中 + 字符 trigram 余弦（512 维哈希）。
- 归一化后 `0.68 × BM25 + 0.32 × cosine`，整句命中加分。
- 返回 `C1..Cn` 引用：论文标题、页码、章节、原文片段、chunk_id。
- 回答必须使用 `[C#]` 标注；前端把引用渲染为可点击徽标，点击跳回阅读器对应页。

## 7. Agent 与工具

实现 14 个真实工具（每个都做数据库/文件操作，不得返回假数据）：

1. `search_papers` 2. `read_paper` 3. `retrieve_chunks` 4. `summarize_paper` 5. `translate_content` 6. `compare_papers` 7. `extract_knowledge` 8. `save_knowledge` 9. `save_annotation` 10. `extract_figures` 11. `analyze_research_gap` 12. `generate_report` 13. `export_document` 14. `search_research_history`

工作流：用户任务 → LLM 决策（最多 5 轮）→ 执行工具 → 记录 step/citation → 继续或流式回答。没有模型时走确定性意图路由（比较/总结/缺口/图表/保存/检索），仍使用真实工具。

写工具 `save_knowledge`、`save_annotation`、`export_document` 在未授权时返回 pending action；`POST /agent/actions/confirm` 才执行。

## 8. 前端设计要求

**视觉方向**：精致、克制、学术感、长时间阅读不疲劳；不要后台管理系统风，不要大面积渐变/发光。

设计 Token（浅色）：
- 背景 `#F7F6F2`，深一档 `#EFEEE8`，卡片 `#FFFFFF`
- 正文 `#171B19`，次级 `#3B4440`，弱化 `#6D7671`
- 边框 `#E4E3DB`，强调色 `#2C6B5D`，金色 `#A97D3D`，危险 `#A6483B`
- 圆角 6/9/12/16/22px；字体 Inter + PingFang SC；阅读区可用 Source Serif 4
- 深色主题：背景 `#111513`、卡片 `#181D1B`、文字 `#ECEFEA`、强调 `#74B7A5`

布局：左侧 258px 导航；顶部 64px；主内容；右侧 336px 上下文栏（小屏隐藏）。移动端 < 1024px 侧栏抽屉，< 900px AI 面板浮层，< 720px 单列。

关键交互：
- 对话：Markdown/公式/代码/表格、引用徽标、来源卡片、Agent 步骤时间线、停止/重生成/复制/保存知识、拖拽上传、模式选择、范围选择。
- 阅读器：pdf.js 连续渲染、自定义文本层、选中文字浮动工具条（5 色高亮/笔记/翻译/复制）、高亮按归一化矩形持久化并刷新恢复、目录/页码/批注三个标签、AI 总结与追问。
- 多论文：选论文、维度、对比结果、来源卡片、自选片段对比、研究缺口。
- 知识库：卡片、筛选、置顶、编辑、删除、图谱 SVG（论文/知识节点与来源边）。
- 设置：资料、模型 Key 测试连接、参数、阅读偏好、语言、主题、数据导出、API 说明、隐私、关于。

## 9. 非功能要求

- 上传 50MB / 400 页限制；PDF 解析在后台任务执行。
- API 超时与模型失败要有可读错误；模型失败时降级到本地抽取并明确提示。
- 所有错误不泄露堆栈与密钥。
- 安全头、CORS 白名单、路径穿越防护、XSS 防护（Markdown 不渲染 raw HTML）。
- 生产环境 SECRET_KEY 必须 ≥32 字符，否则拒绝启动。
- 提供 Dockerfile、docker-compose.yml、.env.example、Nginx 示例、备份脚本。
