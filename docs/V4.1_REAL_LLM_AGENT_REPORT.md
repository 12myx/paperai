## 2. Agent loop

The existing model loop in backend/app/services/agent.py was extended rather than replaced.

~~~text
question
 -> resolve context
 -> model.complete(tools=TOOL_SPECS)
 -> tool calls
 -> registry validation
 -> ownership/scope checks
 -> timeout / budget / duplicate checks
 -> ToolRunner.run
 -> tool result message
 -> next model round (max 8)
 -> final answer
 -> citations + evidence
~~~

Limits from config:

- agent_max_rounds = 8
- agent_max_tool_calls = 20
- agent_timeout_seconds = 240
- agent_tool_timeout_seconds = 45
- agent_token_budget = 30000

The loop now:

- rejects unknown tool names;
- rejects malformed arguments;
- blocks repeated identical tool calls;
- enforces per-tool timeout;
- enforces total time and token budget;
- returns a truthful notice when a limit is reached;
- converts tool exceptions into tool error messages instead of crashing the run.

## 4. Confirmation security

backend/app/services/actions.py issues an HMAC-protected token containing:

- user id
- tool name
- argument digest
- expiry (10 minutes)

The confirmation endpoint:

- rejects missing token;
- rejects token for another user;
- rejects changed arguments;
- rejects expired tokens;
- rejects replay of an already-used token.

The frontend sends action_id with the exact displayed args; the backend does not trust the client args alone.
