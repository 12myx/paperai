# V4.2 Resource Control Report

## 1. Auto retrieval

ChatStreamRequest now has auto_retrieval (default true).

- true: resolver may retrieve question-relevant knowledge/images/artifacts; local pipeline may use RAG.
- false: resolver only includes explicit IDs and project-linked resources; local pipeline uses read_knowledge/read_image/read_artifact for explicit items; search/RAG tools reject with a clear error.
- Frontend exposes an "自动检索" checkbox; browser test confirmed auto_retrieval=false in the actual request body.

Test coverage:

- auto off + explicit knowledge -> read_knowledge, no search/retrieve.
- auto off + no explicit resource -> no automatic search, empty citations, notice.
- tools search_papers/retrieve_chunks/search_knowledge/search_images/list_artifacts reject when auto off.

## 2. Exclusions

ChatStreamRequest already had exclude_ids; V4.2 applies it end-to-end:

- papers are filtered before scope and tools.
- ToolRunner._paper rejects excluded paper IDs.
- _scoped_ids removes excluded IDs.
- _knowledge/_artifact/_figure/_project reject excluded IDs.
- knowledge/image/artifact search results filter excluded IDs.
- project excluded -> project context removed.
- frontend ContextPicker has an exclude mode and sends exclude_ids.

Browser test observed:

~~~text
知识 0 · 图片 0 · 成果 0 · 排除 1
request body includes exclude_ids
~~~

## 3. Permission rules

- All resource reads require authenticated user ownership.
- Project resources require user_id and project_id.
- Explicit IDs are intersected with owned rows.
- Auto retrieval is constrained by project and user.
- Tool parameters cannot bypass ownership/exclusion in the tested paths.

## 4. Resource usage transparency

Implemented:

- SSE start resources includes project, knowledge, images, artifacts, auto_retrieval and excluded_ids.
- Tool timeline shows actual search/read/check calls.
- Final citations show the actual referenced resource IDs/types.
- ContextPicker shows explicit selection and exclusions.

Now implemented:

- Durable resource_usage table and /api/agent/runs/{run_id}/resources endpoint.
- Stages: included, read, referenced (retrieved stage is stored but search-result instrumentation is still partial).
- UI "本次研究资料" panel groups included/read/referenced resources.
- selection_source records explicit/auto/project for included resources.

Still partial:

- Exclude UI covers knowledge, images and artifacts; paper/project exclusion is backend-supported but not a dedicated UI list.
- "Retrieved" is not comprehensively recorded for every search result.
- The UI groups by stage but does not yet explain every single retrieval reason.

Status: PARTIAL, with a real lifecycle ledger now present.
