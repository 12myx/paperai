# V4.2 P0 Figure Library Redesign

> Problem: 62 extracted items were almost all page scans with no captions, shown as a flat "图表" gallery.

## 1. Root cause

- PDF extraction accepted any embedded image above 40x40.
- No page coverage / text density test.
- No requirement for a real Figure/Table caption.
- No separation between page snapshot and figure.
- The UI had only "全部图表 / 已收藏".

## 2. Implemented P0

No PDF reparse and no destructive deletion. Existing Figure rows are classified in place.

New Figure fields:

- detected_kind: figure / table / page_snapshot / unclassified
- quality_score
- caption_confidence
- is_page_snapshot
- ignored
- review_status
- visual_status

Classification rules:

- table_markdown or kind=table -> table
- high page coverage or full-width low-text scan band -> page_snapshot
- caption beginning Figure/Table/图/表 -> figure candidate
- low-confidence images -> unclassified / pending
- no caption -> never enters featured solely by being a large image

Idempotent SQLite migration adds the columns/indexes; PostgreSQL SQL is provided.

## 3. New API behavior

~~~text
GET /api/figures?view=featured|tables|snapshots|pending|saved|all
POST /api/figures/reclassify
PATCH /api/figures/{id} { saved, ignored, review_status, note }
~~~text

The response now includes view counts and detected_kind/quality fields. Default view is featured.

## 4. New UI

- Tabs: 精选图表 / 表格 / 页面快照 / 待确认 / 视觉记录
- Grouped by paper, not one flat grid
- Featured excludes page snapshots and ignored items
- Page snapshot banner: "这是整页扫描，不是图表"
- "这不是图表" feedback marks rejected and hides it
- "保存视觉记录" toggles a durable saved record
- Table entries use table_markdown as visual record content
- "在 Chat 中提问" hands the resource to Chat

- Auto image search excludes ignored and page_snapshot items.
- extract_figures excludes ignored/page snapshots.
- Explicit image selection can still open a page snapshot for source inspection.
- Visual semantics are not claimed; caption/metadata remain distinct.

## 8. Remaining P0/P1 gaps

- Existing 62 page snapshots have no real table records.
- New table extraction renders a cropped PNG snapshot; existing table rows without a stored image require reprocessing to gain a table image. Table markdown remains the text record.
- No visual model; AI explanation is text/caption based and says so.
- New PDF extraction still needs the stronger page-coverage/table detection rules at extraction time (P1), not only lazy classification.
