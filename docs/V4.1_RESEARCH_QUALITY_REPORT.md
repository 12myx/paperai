# V4.1 Research Quality Report

## 1. Evidence model

Existing Evidence types are retained:

- direct: 原文直接证据
- shared: 多篇论文共同支持
- inferred: AI 基于证据的推导
- hypothesis: AI 研究假设
- insufficient: 证据不足
- external: 需要外部验证

No new evidence table was added.

## 2. Resource evidence

Resource citations are stored through existing source_type/source_id:

| Resource | source_type | source_id |
| --- | --- | --- |
| Knowledge | knowledge | knowledge id |
| Image | image | figure id |
| Artifact | artifact | artifact id |
| Project | project | project id |

Knowledge, image, artifact and project evidence is intentionally not auto-verified against a paper chunk. This prevents a user note or caption from being mislabeled as a verified paper quote. Image evidence is caption/metadata evidence, not visual evidence.

## 3. Citation integrity

- Paper citations retain paper id, chunk id, page and quoted text.
- Knowledge/image/artifact/project citations retain resource type and resource id.
- The resolver never invents page numbers; missing page is represented as 0/unknown in the UI and is not claimed as a real page.
- Frontend source cards route to the corresponding resource.
- Artifact quality checks use real citation keys and report issues.

## 4. Verification tests

- Knowledge RAG returns knowledge citation and evidence.
- Project context creates a project citation; project evidence is verified=false because a project goal is not a paper chunk.
- Image tool reads real bytes and explicitly refuses visual claims without a vision provider.
- Artifact quality check returns real issues.
- Mock vision provider test proves bytes are passed to a provider adapter, but this is not a real visual model test.

## 5. Known risks

1. Real model may still hallucinate; citation post-processing and quality checks reduce but do not eliminate this.
2. Visual evidence cannot be verified until a real Vision Provider is configured.
3. No real-model contradiction benchmark.
4. Prompt-injection text in knowledge is treated as data in local tests, but real-model compliance is not verified.
5. Evidence verification is chunk-match based for papers; user notes and image captions are explicitly unverified.
