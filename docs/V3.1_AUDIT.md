## 0. 执行摘要

**结论：当前产品是一个“可运行、可追溯、工程完整”的论文阅读与多论文研究工具，但还不是 V3.1 要求的 AI Research Operating System。**

三个关键判断：

1. **基础层扎实**：P3 前基线为 74 个 API、20 张表、26 个后端测试、21 步浏览器验收；P9 后为 119 个 API、31 张表、71 个测试、38 步浏览器验收。真实 PDF 解析/引用/批注/导出链路已闭环。
2. **P3 前的 Evidence System 只有“引用字段”，没有“证据实体”**：引用存在于消息 JSON 与工具结果中，缺少统一的 Evidence 表、证据类型、可验证性与跨模块复用。**P3 已补齐该底座**（见 EVIDENCE.md）。
3. **P3 前的 Research Intelligence 完全未实现**：没有路由、页面、数据表或导航项。**P5 已补齐资料库范围的研究情报中心**（见第 14 节）；外部学术数据与主题语义聚类仍未实现。

因此，V3.1 不应从“加页面”开始，而应按依赖顺序：**先补 Evidence，再做 Research Intelligence，再升级 Agent 与知识库**。

## 2. 当前真实架构

```
React SPA (11 pages)
  ├─ Home / Chat (SSE, citations, steps, pending actions)
  ├─ Library → Reader (pdf.js, annotations, AI panel)
  ├─ Research (compare, fragments, gap)
  ├─ Knowledge (CRUD, tags, graph)
  ├─ Figures / Projects / History / Settings
  │
  ▼
FastAPI 74 endpoints
  ├─ routers: auth/papers/annotations/figures/chat/research/library/exports/settings
  ├─ services:
  │   ├─ pdf.py       布局解析、章节、图表、表格
  │   ├─ chunking.py  章节感知切片
  │   ├─ retrieval.py BM25 + 字符 trigram
  │   ├─ rag.py       引用召回 + 90s 进程缓存
  │   ├─ tools.py     14 个真实工具
  │   ├─ agent.py     最多 5 轮工具循环 + SSE
  │   ├─ analysis.py  11 种总结 / 批判 / 对比 / 缺口
  │   └─ export.py    6 种真实文件
  ├─ SQLite 20 表（可切 Postgres）
  └─ data/storage 用户隔离文件
```

**已有核心闭环**：上传 → 解析 → 切片 → 检索 → 引用回答 → 阅读器定位 → 批注 → 知识库 → 项目 → 导出。

**缺失的核心闭环**：证据实体化 → 研究情报分析 → 研究机会 → 研究计划 → 成果质检 → 长期研究记忆。

## 4. P3 前 Research Intelligence 现状与可复用资产（历史基线）

### 4.1 现状（P3 前）

当时全仓搜索 `research intelligence`：**0 处**。没有：
- `/app/intelligence` 路由；
- 导航项；
- 数据表（landscape/trend/conflict/opportunity）；
- API；
- 任何页面或组件。

因此当时必须从零建设。P5 已新增 `intelligence` 路由、页面、`intelligence_reports` 表与 4 条 API；本节保留为历史基线。

### 4.2 可复用的真实资产

| 资产 | 位置 | 可复用方式 |
| --- | --- | --- |
| 章节/页码/bbox 切片 | `chunks` 表 | 研究情报的证据定位 |
| 引用召回 | `services/rag.py` | 全景/趋势/冲突的证据候选 |
| 多论文对比 | `/research/compare` | 方法/结论差异的初稿 |
| 研究缺口 | `/research/gap` + `analysis.local_gap_analysis` | 缺口候选与证据 |
| 项目/合集范围 | `projects`, `collections` | 研究情报的 scope |
| 知识库 | `knowledge_items` | 主题信号、个人研究记忆 |
| 导出 | `services/export.py` | 情报报告导出 |
| Agent 工具 | `tools.py` | 新工具 `generate_research_landscape` 等 |

### 4.3 不可直接复用的部分

- 现有对比只在请求时生成，**不落库**，无法做趋势/演化/冲突的持久分析；
- 引用只是消息的一部分，**不是可查询实体**，无法按研究问题/方法/证据强度筛选；
- 没有年份/方法/数据集/指标的结构化字段，无法生成可靠趋势；
- 没有“分析范围”元数据，容易把资料库结论误称为领域结论。

### 4.4 结论

Research Intelligence 的第一阶段必须**限定为用户资料库范围**，并在 UI/API 明确标注 `scope=library`、论文数、年份覆盖；没有外部数据时，禁止展示“全球趋势”。

## 5. 其他关键差距（按模块）

### 5.1 体验与导航

| 目标 | 现状 | 差距 |
| --- | --- | --- |
| 可折叠导航 | 固定 258px | 无折叠 |
| 可调整宽度面板 | 阅读器三栏固定 | 无拖拽/持久化 |
| 快捷键 | ⌘K 搜索、N 新建 | 无快捷键帮助、无阅读器快捷键 |
| 全局搜索 | 顶栏按钮跳到论文库 | 不搜知识/项目/对话/图表 |
| 最近访问 | 无 | 无 |
| 阅读位置恢复 | **只写 localStorage，从不读取** | 刷新/重开回到顶部 |
| 多任务 | 单对话 | 无任务中心/并行任务 |
| 通知 | Toast | 无通知中心/持久通知 |
| 无障碍 | 部分 aria/focus | 无 skip link、焦点陷阱、键盘全流程审计 |

### 5.2 Agent

- `MAX_ROUNDS = 5`，有工具循环与 step 持久化；
- 写操作有 pending action；
- **没有**：计划先行、暂停/恢复、服务端 cancel API、自检报告、任务中心、失败重试策略；
- 客户端 abort 只是断开 SSE，服务端只能靠生成器关闭标记 `cancelled`，不是可查询的任务状态机。

### 5.3 知识库

- 知识搜索是 `title/content ilike`，不是语义；
- 检索索引只覆盖 chunks，不覆盖 knowledge；
- 无自动标签、无重复检测、无聚类、无版本历史；
- 图谱只有“来源边 + 手动边”，没有概念/方法/数据集节点。

### 5.4 多论文

- 有 compare / fragments / gap；
- 无证据矩阵表、无冲突检测、无方法演化、无年份时间线、无实验条件结构化对比；
- 对比结果不落库，无法在 Research Intelligence 中复用。

### 5.5 学术成果

- 有 11 种总结、对比、缺口、6 格式导出；
- 无文献综述、开题报告、研究计划、实验设计、学术 PPT；
- 无 Academic Quality Checker（引用真实性、无依据推断、重复、格式）。

### 5.6 性能与稳定

- 解析用进程内 BackgroundTasks；
- 检索缓存 90 秒，无增量索引版本；
- 无任务队列、无批量上传队列、无大 PDF 分段处理；
- 无 rate limit、无长任务恢复；
- SQLite 单写；Postgres 支持但未实机验证。

## 7. 当前最值得优先升级的五项能力

按“依赖前置 × 用户价值 × 评分/差异化”排序：

### 1）统一 Evidence System（最高优先）

- **理由**：RI、冲突、矩阵、成果质检、导师计划都依赖它；没有它，所有“研究情报”都会变成不可验证的生成文本。
- **产出**：Evidence 表、6 种证据类型、证据抽屉、验证器（quote 是否在 chunk 中）、置信度、跨模块引用。
- **验收**：每条 AI 结论可展开证据；无法定位时明确标记；100% 引用可回溯。

### 2）Research Intelligence MVP（战略差异化）

- **理由**：V3.1 的核心新能力；现有产品只有“对比”，没有“领域认知”。
- **产出**：资料库范围全景、真实年份趋势、研究缺口、观点冲突、证据矩阵、机会推荐。
- **验收**：范围标注、证据引用、无外部数据不编造趋势、每项结论可回溯。

### 3）Agent Task Orchestration v2（产品承诺）

- **理由**：当前只是“工具循环”，还不是可控制的任务系统；用户无法暂停/恢复/查看计划。
- **产出**：计划预览、任务状态机、暂停/取消/重跑、自检报告、任务中心。
- **验收**：复杂任务先出计划；暂停/取消真实生效；自检列出证据不足与失败步骤。

### 4）Knowledge Intelligence（长期价值）

- **理由**：知识库是护城河，但当前只是带标签的文本存储。
- **产出**：自动标签、混合语义检索、去重、聚类、版本历史、跨项目复用、研究记忆。
- **验收**：新问题能召回历史知识；重复内容被识别；版本可回溯。

### 5）Experience Shell（可见质量）

- **理由**：评委与用户第一眼感知；且独立于数据层，可快速见效。
- **产出**：折叠导航、可调面板、全局搜索、最近访问、阅读位置恢复、快捷键、无障碍、通知中心。
- **验收**：键盘全流程；布局持久化；刷新恢复阅读页；搜索跨实体。

## 9. 每阶段验收标准（可执行）

### P1 体验外壳

- [ ] 侧栏可折叠，状态持久化；移动端抽屉正常
- [ ] 阅读器三栏可拖拽调宽，宽度持久化
- [ ] 全局搜索（⌘K）跨论文/知识/项目/对话/图表，键盘上下选择 + Enter 打开
- [ ] 最近访问（论文/项目/对话）可恢复
- [ ] 刷新/重开论文恢复到上次页码
- [ ] 快捷键帮助面板；阅读器支持 j/k/空格/高亮
- [ ] 无障碍：skip link、焦点可见、Modal 焦点陷阱、aria-label
- [ ] Playwright 覆盖以上 7 项；0 console error
- [ ] 深色模式对比度检查通过

### P2 阅读闭环

- [ ] 服务端/本地保存阅读位置，跨设备/刷新恢复
- [ ] 目录与当前页同步高亮
- [ ] 批注可一键“加入证据/知识”
- [ ] 右侧显示“相关知识与证据”
- [ ] 引用点击滚动并高亮目标段落
- [ ] 验收：3 篇论文、10 条批注、刷新恢复

### P3 Evidence System

- [ ] `evidence` 表：paper_id, chunk_id, page, section, quote, type, confidence, verified, source, analysis_id
- [ ] 6 类：direct/shared/inferred/hypothesis/insufficient/external
- [ ] 验证器：quote 必须能在 chunk 原文中找到；不匹配标记 `unverified`
- [ ] 证据抽屉：从回答/总结/对比/知识打开，展示类型、置信度、原文、跳转
- [ ] API：创建/查询/按类型/按论文/按分析结果
- [ ] 回填历史引用；新回答自动写入证据
- [ ] 测试：证据类型、验证、越权、无法定位提示
- [ ] 验收：随机 20 条 AI 结论，100% 可展开证据或明确“证据不足”

### P4 多论文升级

- [ ] 证据矩阵：研究问题 × 论文 × 方法 × 数据集 × 发现 × 证据
- [ ] 冲突检测：观点 A/B、条件、数据集、指标、可比性判断
- [ ] 方法演化：时间线 + 继承/改进关系 + 证据；无证据标“可能”
- [ ] 实验条件对比：数据集、基线、指标、规模
- [ ] 验收：3 篇论文，矩阵可筛选，冲突有可比性说明，演化有依据
- [ ] 无证据时不得生成“改进关系”

### P5 Research Intelligence

- [ ] 路由 `/app/intelligence`，导航项，项目范围选择
- [ ] Landscape：主题、问题、路线、代表论文、挑战、方向；每条带证据/标注推断
- [ ] Trends：仅基于真实年份；无年份/样本不足显示“数据不足”
- [ ] Gaps：区分论文明确指出 vs 多篇共同 vs AI 推导；含证据、置信度、切入点
- [ ] Conflicts：观点、条件、可比性
- [ ] Matrix：研究问题/方法/数据集/发现/证据
- [ ] Connections：主题-论文-方法-概念-数据集-问题；边有依据
