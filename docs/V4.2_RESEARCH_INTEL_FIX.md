# V4.2 多论文研究：观点冲突与方法演化修复

## 1. 问题

用户在“多论文研究 → 观点冲突 / 方法演化”点击生成时看到：

~~~text
服务器内部错误，请稍后重试
~~~

## 2. 根因

两个端点都调用：

~~~python
response = LLMClient(config).complete(...)
payload = _parse_json(response.get("content") or "")
~~~

但 `LLMClient.complete` 是 async，缺少 await，返回 coroutine：

~~~text
AttributeError: 'coroutine' object has no attribute 'get'
~~~

这与之前学术成果的 500 是同一类异步调用错误。

## 3. 修复

在 `multipaper.py` 中：

- `build_conflicts`：`response = await LLMClient(config).complete(...)`
- `build_evolution`：`response = await LLMClient(config).complete(...)`

模型调用失败仍回退本地模式；不会因为模型异常返回 500。

## 6. 注意

- 冲突为空不是错误：只有研究问题相同、数据/指标可比、且有证据时才输出。
- 演化关系为空不是错误：只有原文明确说明继承/改进关系时才输出 explicit。
- 模型失败会回退本地时间线/并列画像，并在 note 中标明。

## 7. 对比维度标签修复

用户反馈：多论文研究里的“+ 研究方法 / 实验设计 / 创新点 / 局限性 / 研究结论 / 可复现性”看起来可选，但结果仍是固定四列。

根因：

- 前端 chip 只把文字追加到输入框，没有选中/取消状态
- 后端本地对比固定使用“研究问题/方法/实验/结论”四列，忽略 focus
- 自定义维度也没有成为对比列

修复：

- chip 改为可切换的选中状态（✓ / +）
- 支持从 focus 中移除已选维度
- 后端按选中维度动态生成对比列
- 支持别名：实验设置/实验，主要结论/结论，复现/可复现性
- 无法匹配任何内置维度时，生成自定义关注列

实测：

~~~text
默认选中：研究方法、实验设计、研究结论
点击“+ 局限性”：选中，输入变为 …、局限性
点击“✓ 实验设计”：取消，输入移除实验设计
开始对比：结果包含局限性、研究方法、研究结论
~~~

新增测试：

- 对比维度改变表格列
- 自定义维度生成自定义列

其他 chip 审计：

- 证据库类型 chip：有 active 状态，驱动 type 参数
- 知识库类型/主题 chip：驱动 kind/cluster 过滤
- 论文库状态/收藏 chip：驱动 status/favorite
- 未发现其他只改变视觉、不进入请求的标签
