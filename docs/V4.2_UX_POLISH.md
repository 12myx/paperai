# V4.2 体验优化：重复保存、搜索相关性、本地提示、阅读密度

> 只处理前三个功能实测中发现的体验问题，不改变核心数据语义。

## 1. Chat 保存重复知识

### 问题

重复保存回答时后端返回 409：

~~~json
{"detail":{"code":"duplicate_knowledge","candidate":{"id":"...","title":"..."}}}
~~~

前端统一显示“保存失败，请重试”，用户误以为功能坏了。

### 修复

- 识别 409 duplicate_knowledge
- 显示“内容已存在于知识库”
- 展示相似度与已有标题
- 提供“打开已有条目”按钮
- 保存按钮变为“内容已存在”，避免重复点击

## 2. 论文搜索相关性

### 问题

搜索 “Grounded” 时，摘要命中的 Contrastive 论文排在标题命中的 Grounded 论文前面。

### 修复

后端 GET /papers?query= 增加匹配优先级：

1. 标题命中
2. 作者命中
3. 摘要命中
4. 其余

实测：

~~~text
Grounded → Grounded Retrieval Augmentation ...（第一）
Contrastive → Contrastive Pretraining ...（第一）
~~~

## 3. 本地模式提示过长

### 问题

每个本地回答前都重复一段长声明，真正内容被推后。

### 修复

统一缩短为：

~~~text
> 本地抽取 · 未配置生成式模型；以下内容仅来自原文，不是生成或推断。
~~~

章节总结尾部也缩短为一行。
不改变本地抽取内容本身，不伪造生成式结果。

## 4. 阅读助手信息密度

### 问题

阅读助手右侧输出长文时占满面板，用户需要大量滚动才能看到操作按钮。

### 修复

- 超过 500 字的总结默认折叠到 300px
- 增加“展开全文 / 收起全文”
- 保留引用点击、证据、保存、导出
- 切换总结模式时自动收起

实测：

~~~text
summary-output-body.collapsed = 1
点击展开全文 → collapsed = 0
~~~

## 8. 知识包“保存到知识库”按钮作用域

截图问题：目标论文已经切换，但“保存到知识库”仍出现。

原因是按钮绑定了任意历史 knowledge_pack 预览，而不是当前所选论文。

修复：

- 只有当前预览知识包的 paper_ids 包含所选论文时才显示保存按钮
- 切换论文后按钮隐藏
- 切回原论文后按钮重新出现
- 预览区自己的保存按钮仍针对预览成果

实测：

~~~text
生成知识包后：保存按钮 1
切换到另一篇论文：保存按钮 0
切回原论文：保存按钮 1
~~~

## 9. 知识包顶部简化

问题：知识包 builder 顶部有重复的“将生成”7 个标签、长说明、刷新按钮，占据过多空间。

修复：

- 删除“将生成”标签行
- 删除长说明
- 删除刷新按钮
- 将内容说明压缩为一行：生成：论文速览、研究问题、方法与数据、主要发现、局限、知识卡、证据表
- 目标论文和预检状态并排
- builder 高度从约 230px 降到约 143px
- 保留“生成知识包 / 查看知识库 / 保存到知识库”
