# V4.2 证据库重定义：证据检查

> 旧问题：证据卡把长 quote 全部铺开；“证据不足”只剩一句“没有原文”，无法看到是哪段 AI 生成内容、为什么不足，也不能跳到生成来源。

## 1. 新定义

证据库不是“原文摘录列表”，而是 **AI 生成内容的证据检查台**：

- 这条结论是否有原文？
- 来自哪篇论文/哪一页/哪个 chunk？
- 如果没有原文，它来自哪段 AI 对话或分析？
- 为什么不足？
- 能否直接跳到原文或生成内容？

证据不足不再被当作“证据”，而是“纳入研究材料前的风险提示”。

## 2. 卡片

每个证据卡压缩为：

- 类型：原文/共识/推导/假设/不足/外部
- 核验状态、置信度
- 生成结论（最多两行）
- 来源：论文 + 页码 或 AI 对话/分析/成果
- 证据不足时显示原因

卡片操作：

- **原文**：直接跳到 PDF 页码 + chunk
- **生成来源**：跳到对话 / 分析 / 成果 / 知识
- **检查**：打开详情
- 复制/删除

长 quote 不再铺满卡片；只在详情中显示。

## 3. 不足详情

“证据不足”详情显示：

- 生成结论
- 为什么不足
- 请勿作为已证实材料的提示
- 生成来源标题与摘要
- 打开生成内容按钮
- 可定位时打开原文按钮
- 删除/复制

跳转目标：

~~~text
message → /app?conversation=...
analysis with paper → /app/papers/{id}
artifact → /app/artifacts?focus=...
knowledge → /app/knowledge?focus=...
annotation → /app/papers/{id}?annotation=...
~~~

## 4. 后端

services/evidence_view.py 为每条证据补充：

- source_label
- source_title
- source_excerpt
- source_url
- source_available
- gap_reason

Message 来源按当前用户过滤，不会通过 source_id 泄露他人对话。

## 5. 交互与密度

- 默认只显示前 30 条
- “加载更多”每次追加 30 条
- 类型 chips 显示数量
- “不足”chip 高亮
- 支持论文/核验状态筛选
- 搜索生成结论、原文、章节

## 6. 实测

- 直接点击原文：跳转到 /app/papers/{paper}?page=1&chunk=...
- 不足筛选：可见 4 条不足记录
- 不足详情：显示原因、生成来源、建议，并可打开生成对话
- 卡片高度约 141px，不再被超长 quote 撑开
- 0 console/page error
