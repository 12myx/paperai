# AI Development Rules

> 本轮 V4 产生的长期规则；适用于后续模块扩展。

1. **真实优先**：任何“已读取/已分析/已生成”的 UI 文案必须有真实后端操作支撑。没有视觉模型时，不得把图注当像素理解；没有模型时，不得把规则模板冒充生成式推理。
2. **权限在服务端**：资源读取必须同时验证 `user_id` 和项目/范围边界。前端传入的 `user_id`、`project_id`、`knowledge_id` 都不可信。
3. **统一证据**：新资源类型必须能映射到 `source_type/source_id` 或正式扩展 Evidence schema；不得把相似文本直接标成已验证原文。
4. **统一上下文**：新资源先进入 `research_context` 的可检索层，再接入 Agent 工具；不要把所有数据直接塞进 prompt。
5. **工具写操作必须 guard**：生成/导出/保存等写操作必须经过用户确认或显式授权，不能由模型静默执行。
6. **不重复造存储**：成果复用 `AcademicArtifact`，项目关联复用 `ProjectItem`，知识复用 `KnowledgeItem`，除非有明确迁移理由。
7. **迁移可回滚**：数据库变更必须提供 migration、旧数据兼容和回滚路径；本 V4 无 schema 变更。
8. **测试证据分层**：本地规则测试、真实模型测试、真实视觉测试必须分开报告，不能混合宣称。
9. **未知能力显式失败**：缺少外部 Provider 时返回 `capability_limited`，不要返回伪造结果。
10. **前端来源可回溯**：每种引用都要有可点击的资源入口；不能只显示不可操作的总分或摘要。

## V4.1 additions

11. **写确认必须服务端绑定**：action token 必须绑定 user、tool、参数 digest 和过期时间；不得只依赖前端按钮。
12. **工具循环有硬预算**：轮数、工具次数、单工具超时、总时间和 Token 都要有上限；上限命中必须如实提示。
13. **工具失败不崩溃**：单个工具失败应作为 tool error 回传模型，不能吞掉或伪造结果。
14. **未知工具拒绝**：只有 registry 中的工具可执行；模型生成的任意名称不得进入 dispatcher。
15. **真实模型与 Mock 分开**：Mock 只能证明协议与权限，不得标记真实模型能力通过。
16. **视觉 Provider 只接受真实图片字节**：文本模型读取图注/路径不得标记为视觉理解。

## V4.2 additions

17. **Action 状态必须持久化**：确认令牌、状态、参数摘要和过期时间必须落库；不得只用进程内 set 做重放保护。
18. **领取必须原子**：pending -> executing 必须使用条件更新/唯一约束；不要宣称 exactly-once 外部副作用，明确 at-most-once claim。
19. **排除规则优先**：exclude_ids 必须同时作用于解析器、工具读取和自动检索。
20. **自动检索开关是后端字段**：不能只改前端图标；关闭后 search/RAG 工具必须拒绝自动检索。
21. **真实模型证据单独记录**：真实 DeepSeek 通过只证明该次 smoke，不自动证明视觉、注入或生产确定性。
22. **密钥只临时使用**：测试密钥通过设置接口加密保存，测试后清除，不写入源码、文档或 Git。
