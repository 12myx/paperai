# V4.2 学术成果升级：论文知识包

> 目标：把“八类学术初稿工作台”改成“选择一篇论文 → 生成知识卡片 → 存入个人知识库”的可信闭环。

## 1. 实测发现

### 1.1 500 服务器内部错误

真实日志：

~~~text
multipaper.py line 174
payload = _parse_json(response.get("content") or "")
AttributeError: 'coroutine' object has no attribute 'get'
~~~

根因：LLMClient.complete 是 async，但 _model_facets 没有 await。

修复：

- _model_facets 改为 async
- response = await LLMClient(config).complete(...)
- ensure_facets 中 await _model_facets(...)

### 1.2 质检失败

截图对应成果：

~~~text
文献综述：资料库 2 篇论文
quality_status: fail
score: 48
证据: 0 条
引用: 0 个
错误: no_evidence, evidence_table_empty
~~~

论文本身是扫描件：

~~~text
chunks: 0
page_chars: 0 / 36
~~~

质检器正确地发现“没有证据”，但产品不应先生成再失败。

## 2. 已实现修复

### 2.1 预检

新增：

~~~text
GET /api/artifacts/preflight?paper_id=...
~~~

返回页数、chunks、字符数、图表数、ready、reason、message。

生成前逻辑：

- 扫描件 / 0 chunks / 文本过少 → 标记不可生成
- 单篇扫描件生成 → 422，不创建空成果
- 多论文范围 → 自动排除不可读论文；全部不可读则 422
- 生成后没有可用引用 → 422，不创建空成果

### 2.2 论文知识包

新增 kind：

~~~text
knowledge_pack
~~~

内容：

- 论文速览
- 研究问题
- 方法与数据
- 主要发现
- 局限
- 可复用知识卡
- 可引用证据
- 证据表

单篇知识包不再触发 small_scope 警告。

### 2.3 保存到个人知识库

新增：

~~~text
POST /api/artifacts/{artifact_id}/save-to-knowledge
~~~

行为：

- 按章节创建 KnowledgeItem
- 绑定论文、页码、chunk、quote、标签
- 写入 KnowledgeMeta
- 自动生成 Markdown 文件（ExportRecord）
- artifact.knowledge_item_ids 持久化
- 重复调用幂等，不会重复创建
- 返回 items、count、export、artifact

### 2.4 UI

新主入口：

~~~text
选择论文 → 预检状态 → 生成知识包 → 保存到知识库
~~~

- 论文下拉选择
- 显示可生成/不可生成及原因
- 显示页数、片段、图表
- 生成知识包
- 保存状态“已存入知识库”
- 8 类旧模板保留为“高级写作草稿”折叠区
- 生成失败不再显示成功 toast
- 质检 fail 显示为失败，不冒充成功

### 2.5 论文绑定修复

实测发现两个会让人误以为“知识包绑定资料库”的问题：

- 旧的 loadArtifacts 在生成后会重新自动选择历史第一条，覆盖刚生成的知识包
- 后端没有强制 knowledge_pack 必须带 paper_ids

修复：

- 生成知识包前清空旧预览，避免失败时仍显示旧高级草稿
- loadArtifacts 不再覆盖已有 selectedId，只允许首次加载自动选择
- 后端强制要求 knowledge_pack 使用 scope_type=papers 且 paper_ids 恰好一篇

实测：

~~~text
POST /artifacts/generate {kind: knowledge_pack, scope_type: all}
→ 422 论文知识包必须明确选择一篇论文，不能绑定整个资料库
~~~

浏览器请求体实测：

~~~text
{"kind":"knowledge_pack","scope_type":"papers","paper_ids":["..."]}
~~~

生成标题：

~~~text
论文知识包：办好职业本科教育必须以技术学科建设为根基
~~~
