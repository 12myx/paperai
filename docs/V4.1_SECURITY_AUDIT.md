# V4.1 Security Audit

> Scope: tool loop, user/project isolation, write confirmation, prompt injection, image access, API keys.
> No production changes; no paid API calls.

## 1. Controls

- All tool resource lookups require authenticated user ownership.
- Paper scope is checked by ToolRunner._paper.
- Knowledge, figure, artifact and project lookups check user_id.
- Project items check user_id and project_id.
- Write tools are classified in WRITE_TOOLS.
- Write actions require a signed action token bound to user, tool, args digest and expiry.
- Tokens are single-use in the current process.
- API keys remain server-side and are not returned in model public status.
- Image files are read through storage.abs_path; arbitrary model paths are not accepted.

## 2. Tested attacks

| Attack | Result |
| --- | --- |
| Foreign knowledge_ids | Excluded by resolver |
| Foreign image_ids | Excluded by resolver |
| Foreign artifact_ids | Excluded by resolver |
| Foreign project_id | Excluded |
| Unknown tool name | Rejected, step error |
| Tampered write args | Token digest mismatch, 400 |
| Replay write action | Used token, 400 |
| Foreign user confirms action | User mismatch, 400 |
| Expired action | Expiry check, 400 |
| Malicious knowledge text | No tool escalation; answer only |
| Write without confirmation | Pending action, no DB write |

## 3. Not verified

- Real model prompt-injection benchmark.
- Multi-process shared replay store; current replay store is in-process.
- Distributed rate limit/cost abuse.
- A dedicated path traversal fuzzer (storage.abs_path check remains).
- Model output hallucination under long context.

## 4. Risk statement

The backend confirmation binding is stronger than a frontend-only hide button: changing the displayed args or reusing a token fails server-side. However, a compromised server process or leaked secret key remains outside this local test scope.
